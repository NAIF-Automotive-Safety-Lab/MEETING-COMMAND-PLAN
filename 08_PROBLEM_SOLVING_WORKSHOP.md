# PROBLEM-SOLVING WORKSHOP

## 1. Requirement Conflict
**Problem:** Two requirements or assumptions pull the architecture in incompatible directions.  
**Hypotheses:** Identify whether the conflict is real, contextual, or caused by incompatible definitions.  
**Constraints:** Controlled baseline, approved scope, disclosure boundary.  
**Alternatives:** Preserve A; preserve B; change requirement; split configuration.  
**Evidence Needed:** Source requirement, configuration identity, acceptance metric.  
**Falsification Test:** Test both interpretations against the same controlled configuration.  
**Decision Criteria:** Explicit technical owner + traceable authority.  
**Owner:** ______  
**Deadline:** ______

## 2. Packaging / Interface Conflict
Problem → Hypotheses → Constraints → Alternatives → Evidence Needed → Falsification Test → Decision Criteria → Owner → Deadline.

Focus: H/R-point dependency, envelope, hardpoints, BIW logic, restraint routing, service access. No vehicle-specific geometry may be invented.

## 3. Kinematic Feasibility
Problem → Hypotheses → Constraints → Alternatives → Evidence Needed → Falsification Test → Decision Criteria → Owner → Deadline.

Focus: motion compatibility, interference, end-stop behavior, joint definition, reset/rebound logic.

## 4. Load / Energy Management Uncertainty
Problem → Hypotheses → Constraints → Alternatives → Evidence Needed → Falsification Test → Decision Criteria → Owner → Deadline.

Focus: measurable force/displacement/energy behavior, structural reactions, asymmetric load sharing, component characterization.

## 5. Testability / Correlation Uncertainty
Problem → Hypotheses → Constraints → Alternatives → Evidence Needed → Falsification Test → Decision Criteria → Owner → Deadline.

Focus: whether the proposed article, instrumentation, data channels and model outputs can support a meaningful comparison.
